# L02 physical marker roots and prepaid control births · 2026-10-24

Every CLI control identity now owns an actual complete measured
`Strong<BirthBank, Option<OriginPermit>>` allocation. Its immutable authentic
producer authority is inside the original value. Destination G and a distinct
producer A pay their whole root groups before the first allocation; same G/A is
deduplicated. Clones and raw views share that physical root, and every remaining
Weak keeps its body fees until deallocation. Original last-Strong value destruction
still occurs at its original statement. This per-allocation invariant covers old
identities retained by getters or snapshots without a finite retainer/arena ratio.

All 15 original production birth sites migrate together: nine Lifecycle, four Cell
and two standalone-stamp sites. Actual capacity-one, length-zero PreparedBirth
backings exist before activation. Lifecycle initialization needs two births; a new
gate two; stale renewal two per CURRENT stale gate; stop at most three; open clear
two; terminal close and terminal clear one each; standalone stamps two. Manual
success owns its actual pre-Source input, including the existing fallback path.
Server normal and Drop cleanup own four independent one-shot inputs. HTTP preserves
the original full-F admission prefix before preparing its control destinations.

The private control contract now requires caller-owned prepared inputs. Mutation
borrows their outer owner and only places values at original birth points; clear,
stop_owned, close and Drop add no fallible marker admission. Existing getters and
Clone need no new quota. Arbitrary closed-pool control births require preparation
before closure. Raw identity equality, canonical key and metadata/runtime pointers,
authority, retry counts/backoff/maxima and original clocks remain covered.

## Refunds and partial preparation

Cutover/BirthBatch register private physical-only Weak keepers for new and displaced
marker fields. Their owner precedes the original table, serial and watch guards,
including cancellation and rollback. The Weak does not retain the original Ticket,
Gate, route or native payload. No-birth failure-stamp writers use a separately paid
three-fields-per-row release backing prepared before Source. Native empty-entry and
certified-entry deletion use two stack keepers outside the native-state guard.

PendingCutover and PendingBatch also own actual partial empty destinations,
whole/current grants and row backings across refusal. They are declared before the
devices guard. The safe borrowed-grant allocator takes the authentic caller grant
only after successful allocation; refusal or unwind leaves it with that outer
owner. The original unsafe allocation body is reused unchanged, with no added
unsafe lines. Count-zero renewal performs no quota admission, including closed pools.

Capacity pruning uses an actual paid ReleaseBatch backing for five fields per
CURRENT row. Its Result admission precedes the first original retain action; a
caller needing zero-availability pruning supplies that real backing beforehand.
This new backing admission may refuse before pruning, an explicit private admission
contract change. Once pruning begins it performs no new collector admission.
All five fields of every row are captured. A fresh version born outside the map
lock makes its Gate persistent Manual/Stopped; Automatic reset needs the same map
lock. Original Gate payload Drop stays in retain.

An initial fixed inline array overflowed the default Windows test stack. Constant
initialization alone did not cover all call shapes. The final paid dynamic backing
removes that large array from Ticket's future. All 30 Lifecycle cases, including
4096-row pruning, pass with `RUST_MIN_STACK` unset.
