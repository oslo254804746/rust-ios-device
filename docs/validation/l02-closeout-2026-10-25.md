## 4. 明确的 OPEN 与 NOT_RUN

### 明确 OPEN 项（设计与边界限制，不可虚标闭合）：
1. **ESP 载荷解密边界**：
   IPsec ESP (protocol 50) 载荷由平台 IPsec SA 密钥加密保护。当前虚拟本地 userspace TUN 适配器无本地 SA 密钥注入机制，明文用户态过滤器无法透视解密密文内容。若密文内封装私有 TCP 流，目前按原生 transformation 边界转发外层数据包；这属于明确的密码学边界，标记为 OPEN。
2. **128MiB 准入配额范围**：
   128MiB 配额是对系统内已准入已知对象池（physical roots, birth banks, tickets, frames）的计量额度，不代表整个操作系统驱动层、未测外部 SDK 堆或全局 RSS 内存的物理绝对上限。

### 明确 NOT_RUN 项：
1. **真机物理硬件变动**：未执行任何真实物理 iOS 设备的重置、抹掉、配对或流量注入操作（`real_device_executed=false`）。
2. **系统底层原生网卡配置**：Linux TUN/TAP、macOS `utun` 及 Windows 物理网卡未进行全局系统级接口创建或网络路由修改，全部测试基于 `UnixDatagram::pair()` 与受控 userspace mock seam。
3. **真实 Darwin/macOS 驱动级原生运行**：macOS 平台仅通过了基于 Darwin 目标平台（`x86_64-apple-darwin` 与 `aarch64-apple-darwin`）的 ABI 与静态类型检查，未在真实 macOS 系统内核中加载驱动运行。
