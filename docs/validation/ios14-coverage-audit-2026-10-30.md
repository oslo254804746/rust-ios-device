# iOS 14 可测范围复核与补测（2026-10-30）

复核结论：原清单并未把当前条件下可执行的入口全部测完，存在前缀分类过宽、只列缺授权而遗漏受控测试，以及只测主命令而未测旧系统参数分支的情况。本轮继续使用同一台 iOS 14.4.2 USB 设备补测；原始数据和精确标识只保存在仓库外 `20261030-ios14-coverage-audit/private/`。

本报告按 CLI 入口、主要传输/参数分支及已暴露 SDK 接口核对；它不代表所有参数组合、错误注入、并发条件，也不代表一台 iOS 14 手机能验证 iOS 15/16 的专属功能。关联 [首轮报告](ios14-2026-10-30.md)、[修复报告](ios14-fixes-2026-10-30.md) 和 [逐入口覆盖表](ios14-2026-10-30-coverage.md)。

291 项逐入口复核后，有实际 CLI 调用记录的入口由首轮 133 项增加到 **161 项，补充 28 项**。未调用的 130 项分别是：当前 14.4.2 版本不适用 42 项、主机隧道管理器 3 项、状态/数据变更未执行 67 项、缺凭据/硬件/受控素材或完整页面 17 项、当前未实现 1 项。主机管理器的 list/stop/serve 不应说成均直接连接 RSD：它们管理隧道对象或自动扫描设备，本轮没有启动超出指定旧系统设备范围的自动管理器。

在本次指定设备、已有授权及现有材料范围内，没有再找到可直接安全执行而完全没有业务调用证据的旧系统设备入口；这不等于 161 项全部正向通过。失败、空结果、仅完成请求及强制结束采样分别保留，下面列出实际边界。

## Viewer 和截图流

补测发现 viewer 在 iOS 14 仍先尝试 CoreDevice 路径，监听启动后即出现 Lockdown 失败。已在 PNG producer 启动时按实际系统版本选择：17 以下使用现有 DTX/legacy 截图路径；现代分支保留原语义。

实际复测又发现默认 Tokio worker 栈溢出。单独对实际 6,383,003 字节 PNG 做 worker 解码成功（1125×2436，10,962,000 字节像素），排除了该样本单独解码必然失败；在捕获链大型 future 边界使用堆固定后，完整 producer 的 future 尺寸约 37,896 字节，capture_frame 约 2,104 字节。没有扩大线程栈、加重试或吞错。此处的隔离诊断不是所有栈占用的逐帧证明；修复前程序崩溃、修复后相同真机流程成功的对照保留在私有记录中。

- **默认 viewer 和 `viewer web`：** `/frame` 和 `/stream` 均取得有效 PNG，约 6.4 MB；通过 `/stop` 原生停止，进程自然 exit 0，Job 已空。
- **`viewer vnc`：** 单个真实 RFB 客户端完成握手并读取 1125×2436、32bpp、10,962,000 字节的完整 RAW 帧，没有发送输入或剪贴板消息；采样后由本机结束服务进程，不称自然收尾通过。
- **`screenshot --stream`：** 首个 multipart 帧是有效 PNG，6,383,003 字节；采样后本机清理，不称长时间流稳定性或自然收尾通过。

初版 VNC 探针为探测监听端口先连接后关闭，会触发服务端客户端错误退出；后续探针直接保留第一次成功连接用于完整 RFB 握手，避免把探针自身造成的断连当作取帧失败。该现象及原始失败记录没有删除。

最新格式化构建在一次重新挂载 DDI 后的额外烟测中曾遇到 Lockdown 错误，未取得具体设备错误码；随后单独查询确认 DDI 挂载、相关截图服务可启动后，原生 viewer 再次取得 frame/stream PNG 并自然 exit 0。该失败仍保留，不将其猜测为固定延时问题，也没有加入自动重试；没有声称验证了任意挂载时序或锁屏状态下的启动稳定性。

## WebInspector / CDP

CDP `/json/version` 返回 200，但 `/json/list` 返回 500。私有 Rust 诊断确认：设备提供连接应用快照，却没有对应的 Listing 回应，发现快照不完整。pymobiledevice3 实测同样只有连接应用快照、没有 Listing，最终返回零页面；两边请求的 selector 与关键字段相同。

这不是已确认的权威空页面列表，故没有把 500 改成 `[]`。当前没有可供选择的完整页面目标；CDP 页面操作、eval、js-shell、Selenium 尚无端到端正例，需要可检查页面及设备返回的完整 Listing。没有自动启动个人浏览器或页面制造素材。

## C / Python SDK

重新构建并验证绑定后，25 个检查全部通过：Python/C 设备枚举、旧式 Lockdown 查询、DeviceSession 的类型/版本/名称查询、apps/files/read_file/logs 服务、Python 同步及异步查询/服务、C 派生句柄与别名保留/释放、已完成查询后的 cancel，以及关闭和销毁。各读取路径的自有 AFC 文件均与 65,813 字节源内容一致，日志实际取得指定条数。

构建清单绑定了当时源码和 DLL/PYD；后续 viewer 仅修改 CLI，394 个与 SDK 相关的源文件/清单仍匹配。这里没有把关闭后的取消验收扩大为在途取消、所有并发条件或全部异常生命周期的真机验证。

## 尚不能算通过的范围

- 已有实测失败/限制继续保留：设备端 Unback 的 `MBDomain rootPath` nil 断言、file-relay 服务端口连接失败、Windows 本地完整符号链接展开。详见修复报告的参考对照。
- 缺正向数据/事件：非空 Energy 指标、真实 HTTP/HAR 事件、新 crash watch 事件、蓝牙 HCI 数据、配对伴侣事件、SpringBoard 启动通知、Wi-Fi 广告与身份关联。
- 缺应用/页面/凭据：本机 146 项安装列表中未观察到 WDA/XCTest runner；没有匹配的监督 P12；没有可检查的完整 WebInspector 页面和允许完整 VendContainer 的受控应用。没有新安装或启动个人应用来绕过条件。
- 当前版本不适用：现代 CoreDevice/RSD/CDTunnel/个性化镜像等。iOS 17 以下不需要开启这条现代隧道；本次 iOS 14 真机没有执行 tunnel start，也没有将不适用或未开启隧道计为设备故障、失败或漏测。另有 iOS 15/16 条件分支，一台 14.4.2 不能代表它们。`crash sysdiagnose` 当前 CLI 明确未实现，不算等待手机素材即可通过。
- 数据、信任、配置或输入变更仍受已有范围限制；Restore/erase、个人应用安装卸载启动终止、激活/监督变更、Wi-Fi/配置修改、HID/剪贴板等没有因覆盖表存在就获得执行授权。

## 回归、程序绑定和设备收尾

viewer 相关主机测试 26 项通过；两个额外的 ignored 尺寸/实际 PNG worker 解码诊断已手动分别执行，各 1 项通过。最终全量 CLI 串行运行是 **2,008 通过、1 失败、24 忽略**。失败为此前已有的 `admission_paired_combined_exact_count_keeps_four_future_window` 的 `assert!(reached)`；它在单独串行复跑时实际执行 1 项并通过，原因仍未确定。没有据单测复跑把全量结果改为全绿，也没有扩大观察时限或放宽断言。本轮只修改 CLI viewer，未重复运行未改变的整个 Core 库测试；前轮结果另见修复报告。

上述失败是主机管理器使用 `FakeSource`、虚构设备身份和 `Behavior::Pending` 的自动化测试，并未连接这台手机或在 iOS 14 上尝试开启隧道。它独立归入主机端回归问题，不计入 iOS 14 真机功能故障或验收阻塞。

最终构建、`cargo fmt --all -- --check`、`git diff --check` 通过。原生 viewer 正向烟测使用的最新程序与 784 个源码/清单文件已做私有哈希绑定，烟测后再次核对一致；SDK 相关 394 个文件仍与绑定构建一致。

本轮受控 AFC 文件及空目录已清理，定位已 reset，最终 DDI 状态明确为未挂载，设备仍为 14.4.2、备份加密仍关闭；没有执行 Restore 或改变信任、监督、Wi-Fi、个人应用数据。
