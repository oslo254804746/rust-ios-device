# iOS 14 问题定位与修复复测（2026-10-30）

本轮继续分析 [iOS 14.4.2 测试报告](ios14-2026-10-30.md) 中的实际失败。仍使用同一台 USB 设备，操作显式指定私有目标标识。保留工作区原有改动，未提交或推送。原始命令、手机材料、控制消息、程序和源码哈希只保存在仓库外 `20261030-ios14-fixes/private/`。

## FPS：读取边界与会话收尾

采样窗口结束时，原实现可能取消已经读入部分 DTX 帧的 future，导致连接被标记不可用，随后的 stop 失败。现保留进行中的单条消息读取，在原清理预算内完成，再发送 stop；错误继续返回，不增加重试或固定延时。

首阶段 FPS 针对性测试 11 项、CoreProfile 8 项、DTX 生命周期 10 项通过。产品命令首次真机采样取得 1 行、4 个帧事件并自然 exit 0，但紧接的新会话仍可能失败。私有诊断取得设备原始错误 `Failed to start the recording: Failed to set the current session`，说明仅保证 stop 写出还不足以验收连续会话。

参考实现的两个连续会话成功；Rust 显式写半关闭的对照也出现同样设备应答，因此未采用猜测性的 shutdown 修复。受控对照观察到 stop 后继续有原始数据、`k=6` 通知，最后出现本 profile channel 的整数 `k=5`。读至该通知后立即创建的三个连续会话均成功；三个通知距 stop 写出约 2.80、1.51、2.15 秒。这是本设备的实际收尾边界证据，不能据此声称所有版本或所有设备资源都已释放。

保留公开 `stop()` 只发送请求的语义，新增单独等待末尾通知的方法供 CLI 使用；只接受当前 profile channel 的 `k=5`，不接受广播或启动前保存的事件。缺通知超时、原始错误保留及数据/通知顺序均有合成回归。第二阶段 FPS 12 项、CoreProfile 10 项通过。

初次产品复测 `count 1、2` 成功，`count 3` 输出 3 行、63 个帧事件后在原五秒清理期限超时。单变量计时探针将采样改为三秒、仅将诊断观察期限放宽，测得待读取完成约 31 毫秒、stop 写入约 0.23 毫秒，而末尾通知在 stop 写出后约 5.53 秒才到达。因此 CLI 清理期限改用既有初始化的三十秒预算，仍等待实际通知，不固定睡眠、不重试、不将超时视为成功。

最终程序连续执行两轮 `count 1、2、3`，未插入等待或重试：六次均自然 exit 0、stderr 为空、进程 Job 已空，分别输出 1、2、3、1、2、3 行；帧事件数分别为 1、46、79、4、52、62，耗时约 3.99、4.37、6.59、2.04、3.93、6.40 秒。连续会话与原先输出后失败的问题已在本设备复测通过。没有用受控动画或独立仪器校验 FPS 数值准确性；iOS 17+ 设备本轮未连接，未将此结果外推到现代分支。

## Unback 与 file-relay 的进一步定位

- 参考 Unback 使用另一个隔离的完整副本；31.36 秒内收到 3,624 次建目录、2,026 次复制和 2 次下载请求，5,652 条状态应答均为 0，随后接收连接终止，未收到操作终止消息。EOF 仍是失败，不能作为成功收尾；仅凭这些控制消息不能判断断连原因，补充的崩溃报告定位如下。
- 后续读取到三份 `BackupAgent2` 崩溃报告；其中一份的时间与本次参考断连对应，另两份对应前轮尝试。按本设备 dyld cache 的 UUID 核对后符号化，三个异常栈的镜像偏移一致，均在 ManifestDB 枚举队列中进入 `-[MBDomain rootPath]`，根路径字段为 nil 时触发 Foundation 断言并 SIGABRT。静态断言文本为 `Domain has no root path (uninstalled app?): %@`。已定位设备端退出机制；报告未记录动态域值，括号内提示不足以确认具体应用已卸载，也不能据此删改清单或提供客户端协议修复。
- 上述名称碰撞是独立的已观察问题，不解释后续 EOF。没有加入猜测性的 keepalive、重试或将 EOF 转为成功。
- file-relay 在参考实现中成功取得服务端口后，usbmux 连接该端口失败，尚未进入 Sources 请求和归档传输阶段。本轮没有声称完成全量输出，也没有为此增加其他服务回退。
- Windows 本地 Unback 的链接限制与设备端 Unback 的断连仍是不同问题；读取现代 Target 字段不等于全量展开通过。
- font-size 的参考查询返回 Accessibility 字典 7 项，但当前 CLI 查询的 5 个字体键均不存在；不将缺键伪造为成功，也未据此推断其他版本或其他查询接口的行为。
