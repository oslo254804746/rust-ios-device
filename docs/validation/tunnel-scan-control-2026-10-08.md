A manager scan now has one checked absolute 30-second budget, starting before its scan-lock wait. The existing shared 15-second discovery budget, independent 15-second candidate budgets, four connection permits and 1-second failure-write budget remain. The whole budget spans paired candidate admission, reconciliation, active connections, successful failure-row removal, failure writes and readiness. It never restarts between these phases. The global clear/close epoch cancels the whole scan; stopping one device continues to cancel only that device after discovery.

Native discovery errors are moved into a scan session immediately after receipt, before another wait. Normal return keeps the original anyhow error and direct IO downcast. Whole expiry or global cancellation returns an acquired paired/List error as primary, retaining the independent timeout/cancellation in a redacted context. Without an acquired primary, global cancellation remains a quiet stop. A stale successful discovery snapshot still cannot admit candidates or mark ready.

Each session reserves one of eight fixed error slots after acquiring the scan lock and before polling a discovery source. Caller Drop freezes an acquired original error in its slot before releasing the lock. Empty or normally returned sessions release the slot. Ordinary clear preserves abandoned history; terminal shutdown closes admission. Full history rejects a ninth scan with the existing CLI resource_limit decision before polling any source. Queued scans reserve no slot. The limit bounds error count, not arbitrary error payload bytes or allocator/RSS usage.

After dropping its scanner, server shutdown includes the retained history in its terminal report. Repeated reports share the same immutable original error objects. Native retirement, original worker joins, status and EOF checks remain independent; no cleanup task is spawned to retain or drain scan errors. Existing server/signal/native error priorities remain ahead of scan history; discovery history precedes a cleanup timeout.

Whole expiry is distinct from a per-device connection failure: it adds no failure backoff and does not newly mark readiness. Candidate deadlines include whole-clock checks before Source contact, metadata reads, attachment queries and publication. Publication and failure-write rollback restore an unobserved displaced row when a poll crosses its deadline. Global metadata reconciliation checks time and epoch before mutation, with removal rollback on a clock crossing. Previously published timely rows and previous readiness remain governed by the existing contracts.
