审查基线是 `1d98dec`，覆盖 Antigravity 的五个本地提交。**不接受“七包全部完成”的结论。**
本轮修复已确认的实现缺陷并复跑主机回归；原 L02 未覆盖的隔离、清理恢复和逐类审计仍为 OPEN。

## 已修复的问题

1. **[P1] 替换时 panic 可在 Registry 锁内退休 NativeLease。** 原发布闭包拥有新 lease，
   局部 Change 又拥有旧 lease；异常退出会重入同一 Registry mutex，且未恢复表行。
   现在交易只借用外部 change/retired 槽，错误和 unwind 均恢复原行，所有 retiring owner
   在 table/ticket/authority/Registry guards 之外销毁。真实私有候选新增 panic 回归验证
   同一旧表节点/incarnation/runtime、可继续访问 Registry、真实 joins/严格 EOF 和退款。

2. **[P1] 恢复流程丢失旧 probe 的 desired-version observation。** same_incarnation
   只比较 device/global identities，不能替代 desired-version。现把原 observation 贯穿
   新候选取消、激活及提交；manual cutover 在其原 intent 锁内核对旧 version，避免嵌套
   fenced ticket 锁。真实外层取消不能再被旧 probe 主错误覆盖。

3. **[P2] 自然死亡的旧行被 get_record 提前删除。** 这让所谓精确替换退化成普通新建，
   候选失败还会丢失旧行。现在保留 ended 精确旧行直到替换成功，测试先让候选失败并核对
   原表证据，再证明成功保留节点、更新 incarnation，返回真实 NEW userspace port。
   同时保持原输出准入顺序：缓存记录先付费，拒绝时 refresh/新候选 Source 均为零；
   进入替换时先释放不再使用的旧输出副本。

4. **[P2] 候选的原始错误被当作 anyhow context 的显示文本隐藏。** 改用明确的
   CandidateFailure context，实际候选 payload 在旧 Source 前预付；既保留原 probe 的
   anyhow downcast/source/deep IO 身份，也保留可独立检查的完整候选 cause。
   scan 不再丢弃旧 probe report，legacy backoff 检查也前置到 Source 之前。
   控制流不再晚建 ProbeFailedError/EndedError Box；原 Ready(Err) 先穿过原期限/authority
   包装，再在外部转为恢复状态，保留既有跨时钟原始错误断言。

5. **[P2] IP-in-IP 解析误丢合法包且越过内层 payload 边界读取。** 修正内层
   Hop-by-Hop、声明长度、IPv4 fragment flags 与外层首片头链检查。原生产实现中新增四例
   实测 16 PASS / 4 FAIL，修复后 20/0；原十六例保留。详见封装修复验证报告。

Unix 满管道回归现在以真实 FD 不可写和实际 writer/桥接背压为前提，先等运行时自己停止
再收集；closed-zero 撤销回归真正耗尽并关闭 bank。未用更大测试栈、放宽超时或弱化旧断言
替代修复。开发过程中的编译失败、一次 stack overflow 及跨时钟回归失败均保留在本会话与失败轮次记录中，不作为验收通过证据。
