# Build cache and worktree maintenance

On 2026-10-09, the interrupted manager/native L04 host measurement and RSS
attribution were completed in `e80f2b2`. The disk investigation found 21 additional
worktrees occupying only 291.9 MiB, each with local changes. They remain intact.
Pending Python/C query and Darwin work also remain unaccepted and available.

The large consumers were approximately 96 GiB in `~/.cache/uv` and 38 GiB in
the primary checkout's `target`. The uv cache contained 156 extracted builds of
`rust-ios-device-tunnel`; cached source/build directories accounted for about
79 GiB and wheel archives for about 18 GiB. Repeated Python package validation
used a new source-archive path each time and left each build in the persistent
cache. [uv documents its local archive cache keys and package cleanup](https://docs.astral.sh/uv/concepts/cache/).

## Applied fix and cleanup

`scripts/artifacts.py` now gives both local wheel installation and sdist
build/installation an explicit cache directory under the existing per-run
`TemporaryDirectory`. The cache remains available through both installed API
checks and is removed on success or exception. The actual sdist is still rebuilt
and installed. Global dependency/tool caching remains available.

The executed cleanup used `uv cache clean rust-ios-device-tunnel`, preserving
other packages and installed environments. After checking no relevant build or
test process was running, 216 ELF executable cache entries in `target/debug/deps`
(23.22 GiB allocated) and Cargo's `target/debug/examples` (4.86 GiB) were removed.
All source trees, Git branches, `target/validation` evidence and archived native
measurement binaries, the current `target/debug/ios`, Cargo libraries and the
registry were retained. Removed executables can be regenerated by Cargo.

The filesystem changed from 98% used / 5.3 GiB available to 31% used /
approximately 129 GiB available. A subsequent real Python package gate left
the global uv cache at approximately 510 MiB and `target` at approximately 10 GiB.
The exact cleanup inventory and validation receipts are retained in
`target/validation/disk-cleanup-2026-10-09/`.

Validation: 75 tooling tests passed, including success, installation-failure and
installed-smoke-failure cache cleanup. The real Python 3.12 wheel/sdist gate
passed with frozen source; both installed API/error checks ran, and the shared
temporary cache and its parent directory were confirmed absent afterward.

## Continuing work

Reuse available worktrees and keep only a small set actively developing separate
deliverables. All agents should use one shared Cargo target directory and the
existing single Rust-job queue; avoid copying build trees into each checkout.
Group implementation and required validation at deliverable boundaries.

Before removing a source worktree, inspect its branch, HEAD and local changes.
Integrate needed work and preserve remaining tracked/untracked edits first.
Then use ordinary `git worktree remove /absolute/path` so Git can refuse a dirty
checkout. Removing a checkout does not delete its branch. The small dirty source
trees are not the urgent disk problem and should not be deleted indiscriminately.

Codex's automatic worktree lifecycle applies to managed worktrees. For those,
use the app's worktree archive action, which saves a recoverable snapshot. The
manually created Git checkouts under this project's sibling directories require
explicit Git maintenance; do not assume the app's retention setting will remove
them. [Official worktree documentation](https://learn.chatgpt.com/docs/environments/git-worktrees).

For future disk checks, compare actual sizes before choosing cleanup:

```bash
df -h .
du -sh target "$HOME/.cache/uv"
git worktree list
uv cache clean rust-ios-device-tunnel
```

Run cache cleanup after relevant package operations have finished. Use uv's
cleanup command rather than directly deleting its internal cache files.
Retain validation evidence before cleaning Rust build outputs.
